## 2026-05-17 - Avoid cryptographic rng for general simulations
**Learning:** The codebase was using `secrets.SystemRandom().randint()` for generating call metrics (duration, waves, intervals) which is a cryptographic operation reading from system entropy (`/dev/urandom`). This adds massive overhead to rapid generation in large-scale simulation threads compared to a pseudo-random number generator.
**Action:** Use standard `random.randint()` for statistical/simulation randomization tasks where cryptographic security is not required, resulting in up to 5-6x speedup in standalone number generation overhead.
## 2024-06-12 - Optimize CallStatistics Dictionary Operations
**Learning:** In this codebase's statistical aggregators (e.g., `CallStatistics`), using the Look Before You Leap (LBYL) pattern (`if key not in dict`) combined with multiple dictionary accesses introduces significant overhead in hot loops. Additionally, dynamic resizing of the dictionary when dealing with a known number of freshers causes further performance degradation.
**Action:** Pre-allocate dictionaries when the size is known (e.g., `number_of_freshers`), use the Easier to Ask for Forgiveness than Permission (EAFP) pattern (`try...except KeyError`), and assign nested dictionary lookups to local variables within hot loops to dramatically improve aggregation speed.
