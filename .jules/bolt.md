## 2026-05-17 - Avoid cryptographic rng for general simulations
**Learning:** The codebase was using `secrets.SystemRandom().randint()` for generating call metrics (duration, waves, intervals) which is a cryptographic operation reading from system entropy (`/dev/urandom`). This adds massive overhead to rapid generation in large-scale simulation threads compared to a pseudo-random number generator.
**Action:** Use standard `random.randint()` for statistical/simulation randomization tasks where cryptographic security is not required, resulting in up to 5-6x speedup in standalone number generation overhead.
## 2026-06-07 - Reverting Optimization
**Learning:** Optimizing `idx = find_free_fresher_index([not fresher.is_alive() for fresher in freshers])` by passing the list directly (`freshers`) to short-circuit `.is_alive()` causes a type mismatch. The code review flagged this because the parameter docstring says it accepts a `list` (implying a list of threads based on usage elsewhere), but at the call site, it was previously given a list of booleans. By passing threads directly, it broke the logic if the function actually relies on boolean values internally (even if it calls `.is_alive()`, the type change is considered a regression or interface mismatch without a signature update).
**Action:** When converting list comprehensions to generators or changing passed argument types, ensure the receiving function's signature, docstrings, and logic fully support the new type. Do not blindly pass threads where booleans were previously passed without updating the interface and verifying it doesn't break.
